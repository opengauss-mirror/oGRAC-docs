# ODBC 多节点负载均衡

## ODBC负载均衡功能说明

首先，ODBC支持客户端在odbc.ini文件中通过参数Servername和Port配置多个节点，其中Servername可设置多个ip，Port设置多个端口，驱动会将ip和端口一对一拼成完整的连接节点，某个节点连接失败会自动轮询下一个节点尝试连接，直到建连成功，客户端不直接感知中间建连失败的节点（可通过日志文件查看连接状态），所有节点都连接失败则程序退出。示例如下：

  ```shell
  Servername=host1,host2,host3
  Port=port1,port2,port3
  ```

在多节点连接功能的基础上，ODBC提供了AutoBalance参数，可在odbc.ini配置文件中通过该参数设置负载均衡策略，在建立连接时依照特定的负载均衡规则将客户端与多节点的连接依次建立在各个节点上，以此实现连接的负载均衡。如果不配置该参数，默认不使用负载均衡功能，按照节点初始顺序依次尝试建连，最终会与节点列表中第一个有效节点成功建立连接。
目前，ODBC支持roundrobin、shuffle、leastconn、priority[n]四种负载均衡模式，用法如下：

- roundrobin：轮询模式，每次新建连接把起点在节点列表上往后移一位，再从该起点沿圆环轮询，但每个节点最多只尝试一次，即与列表中的节点轮流建立连接，示例如下：

  ```shell
  AutoBalance=roundrobin
  ```

- shuffle：随机模式，每次都随机选择列表中的某个节点建立连接，示例如下：

  ```shell
  AutoBalance=shuffle
  ```

- leastconn：最小连接模式，对候选节点依照各节点有效连接数做优先级排序，连接数最少的节点排在前面，优先与连接数少的节点建立连接。该模式会统计通过当前进程使用leastconn模式在每个节点上建立的连接，示例如下：

  ```shell
  AutoBalance=leastconn
  ```

- priority[n]：带优先级的轮询模式，优先对前n个候选节点做轮询建连，n为非负整数。以三个节点为例，如果客户端想要优先在节点1和节点2上执行业务，节点3只作为其他节点故障时的备用节点，可以设置该参数：

  ```shell
  AutoBalance=priority2
  ```

Servername中节点个数与Port端口个数的对应关系仅在以下三种场景下有效，其余场景下会直接失败退出：

1. host和port个数相同，按一对一拼成完整地址。

2. host和port数量为多对一，多个host分别和唯一port拼成完整地址。

3. host和port数量为一对多，host分别和多个port拼成完整地址。

> [!NOTE]说明
>
> - ODBC支持的负载均衡是进程级的负载均衡，对基于同一进程上创建的连接实现负载均衡，不同进程之间相互独立，连接规则相互不影响。
