# Online DDL

## 核心目标

在传统模式下，变更表结构（如加字段、加索引、改字段类型）通常需要对目标表申请排他锁。对于数据量大的表，变更可能持续较长时间，在持锁期间依赖该表的部分 DML/DQL 会等待；在要求 7x24 可用的业务中，这种影响需要尽量降低。

在线表结构变更技术通过缩短排他锁持有时间、分离耗时构建阶段与元数据切换阶段，降低表结构变更对业务的影响，是保障数据库平滑演进和业务连续性的手段之一。在线 DDL 并不意味着所有 DDL 都不会阻塞业务，具体影响取决于操作类型、锁获取阶段、数据规模及集群状态。

在 oGRAC 多写集群中，普通对象 DDL 通常还需要完成逻辑 DDL 的集群同步；而 `CREATE INDEX ONLINE` 和 `REBUILD INDEX ONLINE` 属于特定的在线索引构建路径，当前均不支持在集群模式下使用。在线构建与并行构建不能同时指定，需根据操作类型选择相应的构建方式。

## 工作机制

### 整体流程

变更表结构整体遵循以下流程：获取 DDL Latch（具体锁模式由操作决定）→ 获取对象及父子对象的字典锁 → 执行变更 → 提交逻辑 DDL 并刷新字典缓存 → 释放对象锁和 DDL Latch。

通常情况下，变更操作在开始前会对需要变更的表及其父表和子表申请相应的表级锁。部分阶段仍可能需要排他锁，因此不能将在线 DDL 理解为完全不阻塞 DML。多写集群中的逻辑 DDL 提交后，由 DTC 向存活实例同步，其他实例刷新或失效相关字典缓存后再继续访问对象。

### 影子索引

索引创建操作本身是资源密集型任务。若长时间持有表级排他锁，会放大并发等待；在线构建路径将耗时的索引扫描与最终元数据切换分离，以缩短锁影响范围。

在线索引构建路径采用影子索引，将索引的物理创建和逻辑启用分开。构建阶段先创建不可见的影子索引并扫描表数据，构建期间由表访问路径维护必要的索引变更；构建完成后，再通过短暂的表锁升级完成元数据切换并删除影子对象。

构建扫描使用读取操作发起时刻按当前 `SCN` 可见的已提交数据版本，以避免长时间持有用户事务快照；这只限定索引构建过程的扫描语义，不会改变业务会话配置的事务隔离级别，也不是新增的事务隔离级别。

影子索引可以显著缩短长时间构建阶段的锁影响，但最终切换仍可能等待并发访问结束。该路径当前仅适用于非集群模式；在 oGRAC 多写集群中，`CREATE INDEX ONLINE` 和 `REBUILD INDEX ONLINE` 均不支持，不能据此推断多写集群具备完全无阻塞的在线建索引能力。

### 并行DDL

传统表结构变更通常由单个执行流程完成；在大规模数据场景下，构建时间较长且难以充分利用硬件并行能力。oGRAC 提供并行 DDL，在可并行的构建阶段使用多个工作线程，从而缩短构建耗时，但不改变对象锁、字典刷新和集群同步阶段的影响。

以并行重建索引为例，系统会初始化工作线程池，协调线程根据 `PARALLEL` 指定的并行度分配数据范围，工作线程完成扫描和构建，协调线程汇总结果并写入新的索引段。并行 DDL 主要缩短构建时间，不能消除对象锁、字典刷新或集群同步阶段的影响。由于在线构建与并行构建不能同时指定，在线影子索引路径和并行构建路径应分别评估。

### 数据字典

系统表保存数据库对象的定义和元数据。DC（数据字典缓存）读取系统表并缓存对象信息，以便查找和管理数据库对象，减少重复访问系统表。

Entity 是执行扫描时使用的对象元数据实体。由于表结构会发生变化，系统会维护不同版本的 Entity；打开对象时使用当前有效版本。DDL 执行后，相关 Entity 会被标记为失效，后续访问检查 `chg_scn` 和 `valid` 标记，必要时重新打开对象。

在多写集群中，DDL 提交后由 DTC 将逻辑 DDL 同步到存活实例；远端实例重放相应的字典操作并刷新 DC/Entity。正在执行的查询仍按其快照和对象版本访问，新的访问在字典刷新完成后使用最新定义。

## 多写场景下的边界

- `DTC` 负责逻辑 DDL 的集群同步和字典一致性，不会把所有 DDL 自动转换为在线操作。
- `DLS` 负责跨实例对象锁协调；锁等待、字典失效和最终切换仍可能对 DML 或 DQL 造成短暂影响。
- `DSS` 提供共享文件和块设备访问，不负责 DDL 锁、对象版本或字典可见性。
- 节点处于 `Reform`、恢复或通信异常阶段时，DDL 可能被拒绝或等待集群状态稳定；应在运维窗口确认集群状态后执行。

## 应用场景

以下矩阵用于说明常见操作在典型路径下的并发影响，不代表所有操作均属于在线 DDL；实际锁等待以操作类型、对象依赖和集群状态为准。

| 操作       |  具体操作 | 允许并发DML  | 允许并发DQL | 备注 |
|--------------|--------------|--------------|-------------|------|
| 二级索引操作 | 普通添加二级索引 | 否 | 是 | 构建期间持有目标表锁，会阻塞并发 DML；多写集群还需完成 DDL 同步 |
|              | 在线添加二级索引 | 是 | 是 | 仅适用于非集群模式；开始和最终切换阶段仍可能短暂等待，集群模式不支持 `CREATE INDEX ONLINE` |
|              | 删除二级索引 | 否 | 是 | 删除和字典刷新阶段需要相应锁，特殊对象依赖可能导致额外等待 |
|              | 重命名索引   | 否 | 是 | 主要修改元数据，切换和字典刷新阶段可能短暂等待 |
| 主键操作     | 添加主键     | 否 | 是 | 需要完成约束、索引和字典变更 |
|              | 删除主键     | 否 | 是 | 需要完成约束和字典变更 |
| 列操作       | 添加列       | 否 | 是 | 添加可空列时影响通常较短；默认值或数据变更可能延长锁持有时间 |
|              | 删除列       | 否 | 是 | 需要完成字典和对象版本刷新 |
|              | 重命名列     | 否 | 是 | 主要修改元数据，切换和字典刷新阶段可能短暂等待 |
|              | 更改列类型   | 否 | 是 | 可能涉及数据重写或对象版本切换，具体耗时取决于数据量和操作路径 |

## 最佳实践

### 在业务低峰期操作

虽然在线表结构变更能够减少并发影响，但并非完全无影响。变更期间可能会构建索引树、读取表数据并写入新数据，导致额外的 CPU/IO 消耗，影响数据库性能。

在多写集群执行 DDL 前，应确认集群处于稳定状态，评估 DLS 锁等待和 DTC 字典同步耗时，并预留最终元数据切换及异常回滚的时间窗口。对于 `CREATE INDEX ONLINE`，应先确认运行模式为非集群；集群模式请使用受支持的普通索引创建路径并结合业务低峰安排。
